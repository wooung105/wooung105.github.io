이번 글에서는 블로그를 만들면서 어떤 기능을 생각했고, 그것들을 어떻게 구현했는지 간단하게 정리해 보려고 한다.

처음에는 템플릿을 사용해서 GitHub 블로그를 만들려고 했다. 하지만 찾아본 템플릿 중에는 내 취향에 맞는 것이 보이지 않았다. 그래서 원하는 모습과 기능을 담아 직접 만들기로 했다.

## 기본 구성

글 작성 방식은 Astro가 제공하는 Markdown 지원과 콘텐츠 컬렉션을 활용했다. Markdown 본문을 읽고 렌더링하거나 빌드할 때 정적 HTML을 만드는 기능은 Astro가 제공한다. 이 블로그에서는 그 기능을 바탕으로 `src/content/blog/`에 글을 모으고, 빌드 결과물을 GitHub Pages에 배포한다.

여기에 블로그에 필요한 글 정보와 화면 구성을 정했다. `src/content.config.ts`에는 제목, 날짜, 태그 같은 필드의 검증 규칙을 정의했고, 글 상세 페이지에서는 각 글의 주소를 만들고 Astro가 렌더링한 본문을 공통 레이아웃에 배치했다.

발행할 글을 고르는 기준도 따로 뒀다. `draft: true`인 글은 제외하고 최신 글부터 보여 주도록 `getPublishedPosts()`에 필터와 정렬을 모았다. 홈, Blog, 태그 목록과 글 상세 페이지가 이 함수를 사용하므로 같은 기준으로 글을 가져온다.

## 카테고리 구성

카테고리는 크게 개발, CTF/Wargame, BugbBounty, 블로그/기술문서, 논문/컨퍼런스, 공모전/자격증의 여섯 가지로 나누어 두었다. 각 글에서 다루는 세부 주제는 태그로 구분했다.

이 글은 `블로그/기술문서` 카테고리에 들어가고, `Astro`와 `GitHub Pages` 같은 태그를 가진다. Blog 화면에서는 큰 분류를 선택해 둘러보고, 태그를 누르면 같은 기술을 다룬 글을 모아 볼 수 있다.

카테고리 필터는 페이지에 불러온 글들의 `data-category` 값을 비교해서 구현했다. 선택한 분류에 해당하지 않는 글은 숨기고, 남은 글의 개수를 표시한다. 선택값은 URL의 `?category=`에도 넣었다. 그래야 새로고침하거나 주소를 공유해도 같은 분류를 볼 수 있고, 뒤로 가기를 눌렀을 때도 이전 선택을 복원할 수 있다.

제목이나 키워드가 기억날 때 바로 찾을 수 있도록 홈에는 검색창도 넣었다. 제목, 짧은 설명, 태그를 합쳐 각 글의 `data-search` 속성에 저장하고, 검색어가 그 안에 포함되어 있는지 확인한다. 입력할 때마다 서버에 요청하지 않고 브라우저에서 목록을 걸러 주는 방식이다.

## 블로그의 특색?

다른 블로그를 보면서 같은 주제의 글을 한데 모아 볼 수 있으면 좋겠다는 생각이 들었다. 그래서 ‘시리즈’라는 묶음을 만들었다. 글에 같은 `series` 이름을 지정하면 하나의 시리즈로 모인다.

구현할 때는 발행된 글을 가져와 시리즈 이름을 기준으로 `Map`에 묶었다. 여기서 일반 목록과 다르게 처리한 부분은 정렬이다. 홈에서는 최신 글이 먼저 나와야 하지만, 시리즈에서는 처음 쓴 글부터 읽는 편이 자연스럽다. 따라서 시리즈 안의 글은 오래된 날짜부터 보여 주도록 했다.

시리즈 목록에서는 최근에 글이 추가된 묶음이 먼저 나오고, 홈에도 최대 세 개를 보여 준다.

## 화면 구성

화면은 글 목록을 중심으로 잡고, 옆에는 간단한 프로필을 뒀다. 프로필에는 졸린 표정의 비스카차 이미지를 넣었다. 내 소개와 활동 이력을 볼 수 있는 Resume 페이지도 메뉴에서 따로 연결했다.

처음 홈에는 큰 소개 문구와 최근 글을 강조하는 카드가 있었다. 하지만 최근 글은 아래 목록에서도 볼 수 있어서, 소개 영역과 카드를 덜어내고 시리즈와 최근 기록이 먼저 보이도록 바꿨다. 처음 만든 구성을 그대로 두기보다 실제로 보여 줄 내용에 맞춰 정리한 부분이다. 현재 홈이 비어 보인다면 이런 이유 때문일 것이다.

테마는 라이트 모드와 다크 모드를 모두 사용할 수 있게 했다. 라이트 모드에는 파란색, 다크 모드에는 주황색을 강조색으로 썼다. 전환 버튼도 해와 구름에서 달과 별로 바뀌도록 CSS와 SVG로 만들었다.

테마를 바꾸는 기준은 루트 요소의 `data-theme` 값이다. 배경색, 글자색, 강조색을 CSS 변수로 모아 두고 이 값에 따라 변수들을 바꾼다. 글 목록과 본문, 사이드바가 같은 변수를 사용하기 때문에 화면 전체에 테마가 함께 적용된다.

선택한 테마는 `localStorage`에 저장한다. 다음 글로 이동해도 설정이 이어지도록 공통 레이아웃의 `<head>`에서 저장된 값을 먼저 읽는다. 다크 모드를 선택했는데 밝은 화면이 먼저 나타나는 현상을 줄이기 위한 처리다. 다른 탭에서 설정을 바꾸면 `storage` 이벤트로 함께 반영한다.

모바일에서는 글 목록과 프로필을 한 열로 바꾸고, 썸네일과 글자 크기, 메뉴 간격을 조정했다. 코드가 긴 경우에는 코드 블록 안에서 가로로 넘겨 볼 수 있게 했다. 화면 크기가 달라져도 본문을 읽는 흐름이 이어지도록 맞췄다.

## 주요 파일 역할

앞에서 이야기한 기능들이 모두 한 파일에 들어 있지는 않는다. 글을 읽고 정리하는 부분, 화면에 보여 주는 부분, 공통 디자인을 맡는 부분으로 나눠 뒀다. 구현을 다시 살펴볼 때 기준이 되는 파일들은 아래와 같다.

| 파일 또는 폴더 | 역할 |
| --- | --- |
| `src/content/blog/` | Markdown 글 보관 |
| `src/content.config.ts` | 콘텐츠 로딩 및 글 정보 검증 규칙 정의 |
| `src/lib/posts.ts` | 발행 글 조회, 날짜순 정렬, 시리즈별 분류 |
| `src/lib/categories.ts` | 카테고리 목록 및 아이콘 정의 |
| `src/pages/index.astro` | 홈 화면 구성 및 글 검색 처리 |
| `src/pages/blog.astro` | 글 목록 표시, 카테고리 필터링, 선택값 URL 반영 |
| `src/pages/posts/[...id].astro` | 글별 경로 생성 및 상세 본문 출력 |
| `src/pages/tags/[tag].astro` | 태그별 글 분류 및 페이지 생성 |
| `src/pages/series/` | `index.astro`: 시리즈 목록, `[series].astro`: 시리즈별 글 목록 |
| `src/components/PostList.astro` | 공통 글 목록 출력 및 검색용 문자열 구성 |
| `src/components/ThemeToggle.astro` | 테마 전환 버튼 구성, 전환 처리 및 선택값 저장 |
| `src/layouts/BaseLayout.astro` | 공통 레이아웃·메타데이터 구성 및 초기 테마 적용 |
| `src/styles/global.css` | 공통 스타일, 테마 색상, 반응형 배치 정의 |
| `astro.config.mjs` | 사이트 기본 주소 등 Astro 설정 |
| `.github/workflows/deploy.yml` | 사이트 빌드 및 GitHub Pages 배포 자동화 |

예를 들어 글을 추가할 때는 Markdown 파일을 쓰면 되고, 글을 정렬하는 기준을 바꾸고 싶으면 `posts.ts`를 보면 된다. 공통 메뉴를 바꿀 때는 `BaseLayout.astro`를 수정한다. 자주 함께 바뀌는 것들을 모아 두니 다음에 손볼 곳도 비교적 분명해진다.
